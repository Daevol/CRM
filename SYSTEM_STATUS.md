# Покрытие требований и пробелы

## Что реализовано в прототипе
- FastAPI-приложение с JWT-аутентификацией, CRUD для клиентов, автомобилей, услуг, броней, складских позиций и финансовых транзакций.
- Интеграционные тесты happy-path для базового сценария записи, движения склада и финансовой фиксации.

## Ключевые пробелы относительно ТЗ
- **Безопасность и доступы**: нет ролевой модели, ACL, 2FA, журналов действий, шифрования секретов/данных.
- **Интеграции и каналы**: нет мобильных клиентов, Telegram-миниприложения, real-time уведомлений (WebSocket/Push/SMS/Email), эквайринга, QR-оплаты.
- **Доменные процессы**: отсутствуют модули графика сотрудников, расчёта зарплат/дивидендов, программа лояльности, подписки, промокоды, документооборот, вывод на внешние экраны, аналитика (RFM/LTV/воронки), AI-рекомендации.
- **Склад и финансы**: нет мультисклада, инвентаризаций, шаблонов норм расхода, интеграции с поставщиками, расчёта себестоимости, P&L по направлениям, дебиторки/кредиторки.
- **Видеонаблюдение**: отсутствует привязка камер, расчёт времени на посту, детекция простоев.
- **Инфраструктура**: нет CI/CD, мониторинга, резервного копирования, миграций БД, S3/Redis, hardening и SLA.

## Рекомендации по дальнейшим шагам
1. Ввести ролевую модель (Owner/Admin/Manager/Employee/Client/Supplier) и аудит действий.
2. Добавить фоновые задачи и каналы уведомлений (Celery/Redis + интеграции SMS/Email/Telegram/WebSocket).
3. Расширить доменные модули: график смен, payroll/dividends, подписки и лояльность, документооборот, мультисклад и интеграция с поставщиками.
4. Подготовить инфраструктуру: Alembic-миграции, Docker/Compose, CI/CD, observability, секреты и шифрование.
5. Реализовать мобильный/Telegram-клиентские API и договориться о контракте для фронтенда.
